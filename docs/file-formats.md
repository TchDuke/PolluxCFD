# Форматы файлов PolluxCFD

Задачи хранятся обычным текстом в формате INI: секции в квадратных скобках,
строки `ключ = значение`. Их можно править любым текстовым редактором. Перевод
строки внутри значения (например, в описании) пишется как `\n`.

Пути внутри задач (к сетке, к детали STEP) считаются от каталога программы.

## 2D-задача: `.cfd`

Задача задаёт область одним из трёх способов: фигурами (`[geometry]`),
прямоугольной сеткой (`[mesh] type = rect`) или готовой сеткой
(`[mesh] type = ugr`).

### `[case]`

| Ключ | Смысл |
|---|---|
| `name` | имя задачи, видно в окне |
| `desc` | описание — текст вкладки «Описание» |

### `[geometry]` — область с фигурами

Такую задачу строит конструктор. Сетка генерируется по геометрии при запуске
счёта.

| Ключ | Смысл |
|---|---|
| `Lx`, `Ly` | размеры прямоугольной области |
| `unit` | единица длины (по умолчанию `м`) |
| `shapes` | число фигур |
| `shape0` … | фигура (формат ниже) |
| `refine` | число точек сгущения сетки |
| `refine0` … | точка сгущения: `x y радиус коэффициент` |
| `wallFactor` | во сколько раз шаг сетки у стенки мельче базового (по умолчанию 0.25) |
| `growth` | прирост шага сетки на единицу расстояния от тела (по умолчанию 0.25) |
| `rotor` | `1` — фигуры образуют вращающееся колесо |
| `tipMach` | число Маха конца лопатки вращающегося колеса |

Фигуры:

```ini
shape0 = circle <cx> <cy> <r>
shape1 = box    <cx> <cy> <ширина> <высота> <угол_градусы>
shape2 = tri    <cx> <cy> <r> <угол_градусы>
```

Слово `noslip` в конце строки делает стенку фигуры стенкой прилипания (для
вязкого счёта). Без него стенка — скольжения.

### `[mesh]` — сетка

| Ключ | Смысл |
|---|---|
| `type` | `rect` — прямоугольная сетка, `ugr` — готовая сетка из файла |
| `Lx`, `Ly`, `nx`, `ny` | размеры и число ячеек для `rect` |
| `path` | путь к файлу сетки для `ugr` |

Для `rect` можно поставить в область один круг — секция `[body]`:
`type = circle`, `cx`, `cy`, `r`.

### `[solver]`

| Ключ | Смысл |
|---|---|
| `mode` | `steady` — стационарная задача, `transient` — нестационарная |
| `mach` | число Маха набегающего потока |
| `alpha` | угол атаки в градусах (для сеток `ugr`) |
| `cfl` | число Куранта |
| `order` | порядок схемы: `1` или `2` |
| `viscous` | `1` — считать с вязкостью (Навье—Стокс) |
| `mu` | безразмерная вязкость (для `rect` и `ugr`) |
| `nu` | кинематическая вязкость, м²/с (для задач с фигурами) |
| `density` | плотность сетки задачи с фигурами: `1` — около 900 узлов, `2` — вдвое больше |

### `[bc]` — граничные условия прямоугольной сетки

Ключи `left`, `right`, `bottom`, `top`. Значения:

| Значение | Условие |
|---|---|
| `transmissive` | свободный выход |
| `slipwall` | стенка скольжения |
| `noslipwall` | стенка прилипания |
| `supersonicinflow` | сверхзвуковой вход |
| `subsonicinflow` | дозвуковой вход |
| `subsonicoutflow` | дозвуковой выход |
| `farfield` | дальнее поле (инварианты Римана) |

### `[init]`

`type = uniform` (по умолчанию) — однородный поток; `type = sod` — начальный
разрыв задачи Сода, счёт нестационарный; на графике профиля рядом рисуется
точное решение.

### Пример

```ini
[case]
name=Цилиндр M=2 (головной скачок)
desc=Круглый цилиндр в сверхзвуковом потоке.

[geometry]
Lx=1.6
Ly=1.4
unit=м
shapes=1
shape0=circle 0.6 0.7 0.18

[solver]
mode=steady
cfl=0.4
order=2
mach=2.0
density=2
```

## Готовая сетка: `.ugr`

Неструктурированная треугольная сетка в формате программы Unstruct2D
(J. Blazek). Файл `.ugr` можно открыть и сам по себе, но удобнее ссылаться на
него из `.cfd` (`[mesh] type = ugr`, `path = …`): так задача несёт число Маха,
угол атаки и описание. Сетки примеров лежат в `grids/`.

## 3D-задача: `.cfd3d`

### `[case]`

`name`, `desc` — как у 2D.

### `[domain]`

| Ключ | Смысл |
|---|---|
| `Lx`, `Ly`, `Lz` | размеры области |
| `nx`, `ny`, `nz` | число ячеек по осям |
| `physLengthM` | сколько метров в единице длины области (нужно для оборотов в минуту) |
| `sliceAxis` | ось среза при открытии: `0` — X, `1` — Y, `2` — Z |
| `refineLevel` | `0` — равномерная сетка, `N` — сгущение до N уровней |

### `[flow]`

`inflowMach` — число Маха набегающего потока (`0` — потока нет).

### `[bc]`

Ключи `xmin`, `xmax`, `ymin`, `ymax`, `zmin`, `zmax`. Значения:
`transmissive` (свободный выход), `slipwall` (стенка), `inflow` (вход
набегающего потока), `reservoir` (вход из резервуара).

### `[objects]`

`count = N` и строки `obj0` … `obj{N-1}` из пар `ключ=значение`:

| Ключ | Смысл |
|---|---|
| `kind` | `sphere`, `box`, `cylinder`, `volute` (улитка), `mesh` (деталь из файла) |
| `cx`, `cy`, `cz` | центр тела; он же центр вращения |
| `r`, `h` | радиус и половина высоты (сфера, цилиндр) |
| `hx`, `hy`, `hz` | полуразмеры бруска |
| `ox`, `oy`, `oz` | смещение бруска от центра вращения |
| `r0`, `r1`, `otheta`, `ohalf` | радиусы и окно выхода улитки |
| `rpm` | обороты в минуту (`0` — тело неподвижно) |
| `ax`, `ay`, `az` | ось вращения (по умолчанию 0 0 1) |
| `group` | номер сборки: тела с одним номером выбираются и двигаются вместе |
| `vres` | разрешение детали из файла (делений по наибольшей стороне) |

Для `kind=mesh` путь к файлу STEP пишется отдельным ключом `obj<N>file`.

### `[groups]`

Имена сборок: `g<номер> = имя`.

### Пример

```ini
[case]
name = Поток + вращающийся цилиндр

[domain]
Lx = 2.0
Ly = 1.0
Lz = 1.0
nx = 64
ny = 32
nz = 32
physLengthM = 0.3

[flow]
inflowMach = 0.3

[bc]
xmin = inflow
xmax = transmissive
ymin = slipwall
ymax = slipwall
zmin = slipwall
zmax = slipwall

[objects]
count = 1
obj0 = kind=cylinder cx=0.6 cy=0.5 cz=0.5 r=0.12 h=0.5 rpm=20000 ax=0 ay=0 az=1
```

## Детали САПР: `.step`, `.stp`

Деталь импортируется в открытую 3D-задачу: **Файл → Импорт 3D тела...**.
